# The Mathematics & Methods Canon for a Self-Learning NQ Quant Shop

## 1. The López de Prado Canon (Advances in Financial Machine Learning)

### 1.1 Purged & embargoed cross-validation — [PARTIAL]

**Plain terms.** Ordinary k-fold CV shuffles data randomly into folds. On time series this lies, because a "test" observation and a "training" observation can be built from the *same underlying price path* — the model is quizzed on questions it has already seen the answers to. Purging deletes training samples whose label-formation windows overlap the test fold in time; embargoing additionally deletes a buffer of training samples *after* the test fold, because serial correlation lets post-test data echo test-period information backward into training.

**Math intuition.** The failure is a violation of independence between train and test, driven by label overlap: if label *i* is computed from returns over [tᵢ, tᵢ+h] (e.g., a 30-bar forward window), any two labels whose windows share even one bar are statistically entangled. Purging removes from training every observation whose window intersects any test-label window (on both sides of the fold). Embargo then removes an additional fraction (LdP suggests ~1% of observations) after the test block — leakage via slow-decaying autocorrelation in features (volatility, volume regimes persist). The result is that CV scores stop being systematically optimistic; LdP shows unpurged CV can make pure noise look like skill. The combinatorial extension (CPCV) generates many train/test partitions to produce a *distribution* of out-of-sample paths rather than one.

**Why it matters.** Every hyperparameter chosen by leaky CV is chosen partly for its ability to exploit leakage, not edge. This inflates the whole downstream trial ledger with falsely strong candidates.

**Shop status.** Era-splits are a coarse-grained purge (whole eras are disjoint), so the shop is protected at the macro level. What's missing is *within-era* hygiene: any model tuning done inside the discover era with k-fold CV is still leaky if labels overlap. Purging/embargo is a cheap upgrade to the refinement search's inner loop.

**Plugs in at:** refinement search (inner-loop model selection and hyperparameter tuning inside the discover era); validation bars (any CV-based score reported to the ledger should be purged/embargoed or it overstates).

### 1.2 Triple-barrier labeling — [NEW]

**Plain terms.** Instead of labeling "did price go up in the next N bars," label each entry the way a real trade resolves: profit-target barrier above, stop barrier below, time barrier ahead. The label is whichever barrier gets hit first. It makes the ML target *isomorphic to the P&L mechanics* of an actual position.

**Math intuition.** Fixed-horizon labels are noise-dominated because the horizon is arbitrary and volatility varies: a +0.2% move in a quiet hour and in a wild hour get the same label. Triple-barrier sets the horizontal barriers as multiples of rolling volatility (e.g., ±2σ̂ₜ), so the label asks "did a *meaningful, path-dependent* move occur," and the vertical (time) barrier encodes that capital tied up in nothing is a cost. Labels: +1 (upper first), −1 (lower first), 0 or sign-of-return (time barrier first). Because barriers mirror bracket orders, a classifier trained on these labels is directly answering the question the execution layer will ask.

**Why it matters.** For a shop whose agent layer manages exits, labels that ignore path (stop-outs) train models that systematically misjudge trades that "would have worked eventually" but die at the stop first.

**Plugs in at:** refinement search (label construction for any supervised component; align barrier multiples with the live bracket/exit logic so the model learns the game actually being played).

### 1.3 Meta-labeling — [NEW — high relevance]

**Plain terms.** Keep your existing signal (the "primary model") deciding *direction*; train a second model that only decides *whether to take the trade and how big*. The meta-model sees the primary signal's context — regime, volatility, time of day, recent primary-model accuracy, microstructure state — and outputs P(this trade wins).

**Math intuition.** Decompose the classification problem: the primary model fixes recall (it surfaces most opportunities, cheaply); the meta-model raises precision by vetoing low-confidence trades. Since F1 is the harmonic mean of precision and recall, filtering false positives from an already-decent primary signal moves F1 more efficiently than trying to train one monolithic model to do side + size + timing at once. It also converts an uninterpretable "one big model" into an auditable two-stage system: you can attribute failures to "signal was wrong" vs "filter was wrong." Trained properly, the meta-model's probability output is a natural sizing input (higher confidence → larger fraction of the risk budget, e.g., via probability-to-size mapping).

**Why it matters / shop relevance.** The shop already runs an agent layer managing *exits*; meta-labeling is the mirror-image discipline on *entries*. It is also the cleanest way to bolt ML onto rule-based signals without discarding them — the ML never overrides direction, only participation and size, which caps the damage a bad model can do.

**Plugs in at:** refinement search (second-stage model over existing signals); sizing (P(win) as a size modulator); validation bars (the meta-model is itself a trial — it goes in the ledger and must survive era-splits like everything else).

### 1.4 Sample uniqueness & weights, sequential bootstrap — [NEW]

**Plain terms.** When trade labels overlap in time (a new signal fires while the previous trade is still open), your "1,000 training samples" might really be 150 independent bets photocopied. Models trained on photocopies are overconfident, and bootstrap/bagging that samples uniformly re-draws the same information repeatedly.

**Math intuition.** Define concurrency cₜ = number of labels whose formation windows span bar t. The uniqueness of a label at t is 1/cₜ; a label's *average uniqueness* is the mean over its lifespan. Two fixes: (1) weight each training sample by its uniqueness (and optionally by the absolute return attributed to it), so the loss function stops over-rewarding redundant observations; (2) *sequential bootstrap*: draw bootstrap samples with probability proportional to how unique a candidate is *given what's already drawn*, so each bagged tree/model sees a maximally independent picture. The same arithmetic gives you the honest effective sample size — which is also the T you should be feeding into significance math (a Sharpe t-stat computed on overlapping trades has far fewer degrees of freedom than trade count suggests).

**Why it matters.** Overlap inflates both model confidence and statistical significance. On a 1-minute NQ strategy with multi-bar holds, overlap is the norm, not the exception.

**Plugs in at:** refinement search (training-sample weighting, bagging); validation bars (effective-N correction when computing significance of per-trade statistics; feeds honest T into DSR/PSR).

### 1.5 Fractional differentiation — [NEW, lower priority]

**Plain terms.** Prices trend (memory, but non-stationary); returns are stationary (but memoryless — differencing wipes out where price *is* relative to its history). Fractional differentiation differences a series by a non-integer amount d ∈ (0,1): just enough to make it stationary, keeping as much memory as possible.

**Math intuition.** The differencing operator (1−B)^d expands into an infinite weighted sum of past values with weights ωₖ = −ωₖ₋₁·(d−k+1)/k — a slowly decaying tail rather than the {1, −1} of plain returns. Fixed-width FFD truncates weights below a threshold so every observation uses the same window (no drift artifacts). Procedure: find the smallest d whose FFD series passes an ADF stationarity test; LdP reports d < 0.6 sufficed for ~87 of the most liquid futures — i.e., taking plain returns (d = 1) systematically over-differences and throws away predictive memory.

**Why it matters.** Mainly a feature-engineering tool for ML inputs: features that carry level/trend context while remaining valid inputs for stationarity-assuming learners. For a shop running mostly signal-rule strategies it is optional; it becomes relevant the moment price-level-derived features enter a model.

**Plugs in at:** refinement search (feature engineering only; no impact on validation, portfolio, or sizing).

### 1.6 DSR and PBO in depth — [COVERED — in implementation; deepen with effective-trial correction]

**Plain terms.** DSR answers: "given how many things we tried, is the best backtest's Sharpe still impressive, or is it just the lottery winner among many tickets?" PBO answers a different question: "when we pick the in-sample winner, how often does that winner land in the *bottom half* out-of-sample?" — a measure of whether your selection process itself has any skill.

**Math intuition.** Two moving parts.
- *Probabilistic Sharpe Ratio*: PSR(SR\*) = Φ[ (SR − SR\*)·√(T−1) / √(1 − γ₃·SR + ((γ₄−1)/4)·SR²) ] — the probability the true Sharpe exceeds threshold SR\*, penalized for short track records, negative skew (γ₃), and fat tails (γ₄).
- *False Strategy Theorem*: among N independent zero-edge trials whose Sharpes have cross-sectional variance V, the *expected maximum* Sharpe is approximately E[max SR] ≈ √V · [ (1−γ)·Φ⁻¹(1−1/N) + γ·Φ⁻¹(1−1/(Ne)) ], γ ≈ 0.5772 (Euler–Mascheroni). After 1,000 independent null trials the expected best Sharpe is ≈ 3.26·√V-scaled — spectacular by construction. **DSR = PSR evaluated at SR\* = E[max SR]**: your winner must beat the best result luck alone would have produced. The two inputs the trial ledger must supply: **N** (trials) and **V** (variance across trial Sharpes).
- *Why nested grids inflate nominal trial counts*: trials multiply across grid axes — 10 lookbacks × 5 thresholds × 3 exit rules = 150 nominal trials, and adding one more axis multiplies again; people then under-report by counting only "finalists." But the correction runs both ways: correlated configurations (lookback 20 vs 21) are not independent draws, so *effective* N < nominal N. LdP's fix: cluster the trial return series (e.g., ONC clustering) and use the number of clusters as effective N, with V computed across cluster representatives. An honest ledger records *everything* (including abandoned trials — they were draws from the lottery too), then deflates to effective independent trials.
- *PBO via CSCV*: split the trial-returns matrix into S blocks, form all (S choose S/2) train/test recombinations; in each, rank strategies in-sample, find the IS winner's OOS rank; PBO = fraction of recombinations where the IS winner falls below OOS median. Model-free, symmetric, and — usefully — also yields performance-degradation and probability-of-loss estimates.

**Why it matters.** These are the mathematical spine of the shop's multiple-testing honesty. The subtle implementation risk is feeding DSR a flattering N.

**Plugs in at:** validation bars (final gate); trial ledger (must capture all trials incl. nested grid axes and abandoned lines; add correlation-clustering to produce effective N and honest V for the teammate's DSR implementation).

## 2. Multiple Testing Beyond DSR/PBO — [NEW: formal joint tests; PARTIAL: philosophy already embodied]

**Plain terms.** DSR deflates one winner's Sharpe. But sometimes the question is different: "out of this whole family of strategies we searched, does the *best one* genuinely beat a benchmark?" (White's Reality Check), "same question but with a fairer, more powerful test" (Hansen's SPA), "*which specific ones* are real?" (Romano–Wolf StepM), and "we accept some duds — what fraction of our accepted strategies are false?" (FDR).

**Math intuition.**
- *White's Reality Check (2000)*: null = even the best strategy in the pool has no expected outperformance vs benchmark. Compute each strategy's performance differential vs benchmark, bootstrap the time series jointly (stationary bootstrap, preserving cross-strategy dependence), and compare the observed max statistic to the bootstrap distribution of maxima. Crucially it accounts for correlation among strategies — the shop's permutation-null machinery is a close philosophical cousin (both build the null by resampling), but RC tests the *family maximum*, not one strategy at a time.
- *Hansen's SPA (2005)*: RC is conservative because its null distribution assumes the "least favorable configuration" — every strategy exactly zero edge — so stuffing the pool with garbage strategies drags down power and can hide a real winner. SPA studentizes each statistic (scales by its own volatility) and re-centers using a data-dependent null that effectively discards clearly inferior strategies. Same question as RC, better power. Practical rule: **RC/SPA when the question is "did our whole search find anything at all."**
- *Romano–Wolf StepM (2005)*: stepwise FWER-controlling procedure that identifies *which* strategies outperform, not just whether the best does — reject the top one, remove it, re-test, repeat. More powerful than single-step because it exploits joint dependence.
- *FWER vs FDR*: FWER = P(≥1 false positive) — Bonferroni-style, brutal at scale; right when a single false go-live decision is expensive. FDR = expected *fraction* of false positives among accepted — Benjamini–Hochberg: sort p-values, accept all p(i) ≤ (i/m)·q. Right for the discovery funnel, where you deliberately tolerate, say, 10% duds among promoted candidates to keep power high. The clean policy: **FDR at the discover→validate promotion gate; FWER-grade evidence (DSR / SPA / StepM) at the validate→holdout→live gate.** (Harvey–Liu–Zhu's cross-sectional work lands in the same place: after multiple-testing correction, a newly claimed edge should clear roughly t > 3, not t > 2.)

**Why it matters.** A self-learning system is a multiple-testing machine by construction — it will run orders of magnitude more trials than a human team, so the correction machinery is not hygiene, it is the core control loop. RC/SPA additionally answer a question DSR does not: whether the *search process itself* is finding real structure vs mining noise, which is exactly the health metric a self-learning agent should track about itself over time.

**Plugs in at:** validation bars (SPA/StepM as periodic "is the whole research program finding anything" audits over the trial ledger; DSR remains per-candidate); trial ledger (two-tier decision policy: BH-FDR at promotion, FWER-grade at go-live).

**Sources:** [Hsu & Kuan, RC + SPA on technical analysis (SSRN)](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=685361) · [Hsu & Kuan PDF](https://homepage.ntu.edu.tw/~ckuan/pdf/snoop01.pdf) · [Corradi & Swanson, "The White Reality Check and Extensions"](https://econweb.rutgers.edu/nswanson/papers/corradi_swanson_whitefest_1108_2011_09_06.pdf) · [Romano & Wolf, "Stepwise Multiple Testing as Formalized Data Snooping" (Econometrica 2005)](https://users.ssc.wisc.edu/~behansen/718/RomanoWolf2005.pdf) · [Practitioner's guide to multiple testing error rates (arXiv)](https://arxiv.org/pdf/1304.4920) · [FDR vs FWER (Casual Inference)](https://lmc2179.github.io/posts/fdr.html) · [Statsig: Bonferroni vs Benjamini–Hochberg](https://www.statsig.com/blog/controlling-type-i-errors-bonferroni-benjamini-hochberg) · [Technical analysis and discrete FDR (arXiv)](https://arxiv.org/pdf/1811.06766)

## 3. Walk-Forward Analysis — [PARTIAL — era-splits cover the static question; WFA validates the *retraining policy*]

**Plain terms.** Optimize on a window, trade the next slice with those frozen parameters, slide forward, repeat; stitch the out-of-sample slices into one equity curve. *Anchored* = training window grows from a fixed start; *rolling* = fixed-length window that forgets old data. WFA doesn't just test a strategy — it tests the *operating procedure* "re-fit every K weeks on the last M months," which is what the shop will actually run in production.

**Math intuition.** The stitched OOS curve is an unbiased estimate of what the *rule + refit schedule* would have earned — a different object from era-split validation, which asks "does this fixed configuration hold up across disjoint regimes with one untouched holdout?" WFA asks "does the process of periodically re-estimating parameters produce live-like returns?" Both are needed: era-splits catch regime fragility; WFA catches parameter instability and tells you whether re-fitting helps or just chases noise. Key diagnostic: walk-forward efficiency (OOS performance ÷ IS performance) — healthy systems run WFE well above ~0.5; also watch whether the chosen parameters jump wildly fold-to-fold (instability = the optimizer is fitting noise). Rolling adapts fast but has fewer data per fit; anchored is stabler but overfitting becomes *harder to detect* late in the sample because with enough training data almost any parameter set looks fine.

**Failure modes (WFA's own overfitting).** (1) *Second-order overfitting*: tuning the WFA configuration itself — window lengths, step size, anchored-vs-rolling — until the stitched curve looks good. Every WFA configuration tried is a trial; ledger it. (2) *Single-path illusion*: classic WFA yields exactly one OOS path — no distribution, so a lucky path passes; combinatorial CV/era machinery is the antidote and complement. (3) *Regime-boundary luck*: fold boundaries accidentally aligned with regime shifts flatter or damn a strategy; vary boundaries. (4) *Holdout erosion*: repeatedly consulting the same final segment across many WFA runs quietly converts holdout into training data.

**Why it matters.** A self-learning shop *is* a walk-forward process — the agent refines strategies continuously. WFA is the honest simulation of that loop, and it is the only tool here that validates the refresh cadence itself (how often to re-fit, how much history to use).

**Plugs in at:** validation bars (WFA as a complementary bar between era-split validation and holdout, specifically to certify the re-fit schedule); refinement search (WFE and parameter-stability-across-folds as robustness scores); trial ledger (each WFA configuration = a trial).

**Sources:** [Susan Potter: Anchored vs rolling WFO](https://www.susanpotter.net/quant/walk-forward-optimization/) · [QuantInsti: Walk-forward optimization](https://blog.quantinsti.com/walk-forward-optimization-introduction/) · [Quanthop: Walk-forward analysis](https://quanthop.com/learn/validation-robustness/walk-forward-analysis) · [Benzinga/Sahm: WFA — when it's truly useful](https://www.sahmcapital.com/news/content/walk-forward-analysis-in-trading-what-it-is-how-it-works-and-when-its-truly-useful-2026-05-12) · [Hypothesis-driven walk-forward validation for microstructure signals (arXiv)](https://arxiv.org/pdf/2512.12924)

## 4. Regime Detection — [NEW]

**Plain terms.** Markets alternate between persistent "moods" — quiet grind, high-vol chop, trending panic. Three trader-usable tools, in ascending complexity: (a) *volatility filters*: is realized vol above/below its rolling percentile — a two-line regime model; (b) *HMMs*: assume an unobserved state variable that switches between a small number of regimes, each with its own return/vol distribution, and infer today's state from observed data; (c) *change-point detection*: don't model regimes at all, just detect *when the data-generating process shifted* (CUSUM, Bayesian online change-point detection).

**Math intuition.** An HMM is defined by a transition matrix (regimes are sticky — P(stay) ≈ 0.95+ daily is typical) and per-state emission distributions (state 1: low vol/mild drift; state 2: high vol/negative skew); Baum–Welch/EM fits it, and the *filtered* probability P(state today | data up to today) is the tradeable output. The cardinal live-use rule: never use *smoothed* probabilities (which condition on the future) in a backtest — that is lookahead, and it is the single most common way regime backtests lie. CUSUM accumulates deviations from a reference mean and flags when the running sum crosses a threshold — it is the "has something actually changed" alarm and needs no distributional model. BOCPD maintains a posterior over "run length since last change," governed by a hazard rate λ (small λ = expect frequent changes = trigger-happy; large λ = smoother). Empirically, simple vol-percentile filters capture most of the practical benefit of HMMs on futures — because the dominant regime axis in index futures *is* volatility.

**Overfitting risk — the part that matters most here.** A regime model is itself a fitted model: (1) *state proliferation* — every extra state absorbs historical anomalies and looks better in-sample; discipline is 2–3 states, chosen a priori; (2) *trial multiplication* — "strategy × regime-filter" grids multiply the ledger's nominal trial count (every regime definition tried against every strategy is a trial; a regime filter that rescues a dead strategy in-sample is the classic overfit); (3) *unsupervised ambiguity* — no ground truth exists for "the true regime," so regime labels can't be validated directly, only through out-of-sample P&L of decisions conditioned on them.

**Why it matters.** The funded-account constraint makes regime awareness asymmetric: a regime filter that merely *stands aside* in hostile states cheaply protects the trailing-drawdown line, whereas a regime model that *switches direction/strategy* is a far bigger claim requiring far more evidence.

**Plugs in at:** sizing (vol-regime filter as risk throttle — the humble, robust version, first priority); refinement search (regime features as meta-labeling inputs; every regime configuration ledgered as a trial); validation bars (regime-conditioned strategies must pass era-splits *within* each claimed regime, using filtered — never smoothed — state estimates); execution (stand-aside filters).

**Sources:** [QuestDB: Market regime detection with HMMs](https://questdb.com/glossary/market-regime-detection-using-hidden-markov-models/) · [QuantStart: HMM regime detection](https://www.quantstart.com/articles/market-regime-detection-using-hidden-markov-models-in-qstrader/) · [QuantifiedStrategies: HMM market regimes](https://www.quantifiedstrategies.com/hidden-markov-model-market-regimes-how-hmm-detects-market-regimes-in-trading-strategies/) · [BSIC: Regime detection and risk allocation](https://bsic.it/regime-detection-and-risk-allocation-using-hidden-markov-models/) · [BOCPD in finance (Financial Internet Quarterly)](https://journals.wsiz.edu.pl/fiq/article/view/525) · [BOCPD for financial time series (ACM)](https://dl.acm.org/doi/10.1145/3795154.3795291) · [PELT change-point detection in finance (ACM)](https://dl.acm.org/doi/10.1145/3773365.3773532)

## 5. Position Sizing Under a Hard Drawdown Constraint — [PARTIAL — MC funded-sim measures ruin; the sizing *rules* are new]

**Plain terms.** Kelly says: bet the fraction of capital that maximizes long-run compound growth. Full Kelly is mathematically optimal and practically unusable — the ride is violent. Fractional Kelly (bet a fraction c of the Kelly size) gives up a little growth for a lot of drawdown relief. Under a prop-firm trailing drawdown, none of this applies to the nominal account: **a $50k account with a $2k EOD-trailing drawdown is, for ruin purposes, a $2k account.** All sizing math must run on the distance to the trailing line, not on account equity.

**Math intuition.** Continuous approximation: optimal fraction f\* = μ/σ² (edge over variance); growth rate g(f) = fμ − f²σ²/2 is a parabola — betting *twice* Kelly gives zero growth with maximal pain, and the penalty for oversizing is worse than for undersizing (the curve is asymmetric in consequences). At fraction c of full Kelly, growth = c(2−c) of maximum — half Kelly keeps 75% of the growth. The killer fact for a drawdown-constrained shop: for a continuous Kelly bettor at fraction c, the probability of *ever* seeing wealth fall to fraction x of its peak is approximately x^(2/c − 1). Full Kelly (c=1): P(halving) = 50%, P(losing 90%) = 10% — guaranteed funded-account death. Half Kelly: P(halving) = 12.5%. The trailing line makes even these numbers too generous, because the floor ratchets up with every new equity high — you cannot "ride out" a drawdown that a static-floor gambler could.
*Drawdown-constrained sizing (Grossman–Zhou / CPPI logic)*: to maximize growth subject to never breaching a drawdown floor, bet proportional to the **cushion** — risky exposure ∝ f\* × (equity − floor). For the shop: cushion_t = equity_t − (EOD peak_t − $2,000); risk per trade = fixed fraction of *cushion*. Sizes then shrink automatically as the line approaches (ruin probability collapses) and re-expand as buffer is rebuilt. This is the mathematically correct generalization of the folk rule "risk 1% of remaining drawdown buffer."
*Volatility targeting*: size = (target daily $ vol) / (realized vol per contract). On NQ, where vol varies 3–5× between quiet and wild weeks, constant-contract sizing means your *actual* risk is set by the market's mood, not by you. Empirically vol targeting raises Sharpe on equity-index exposure (e.g., ~0.40 → ~0.50 unscaled vs scaled) and cuts drawdowns, partly via an implicit momentum/leverage effect. The complete sizing stack composes: **contracts = min(vol-target size, k × cushion-fraction size, c × Kelly-from-edge-estimates)** — with Kelly estimated conservatively (edge estimates are noisy; noise in μ pushes realized betting past true Kelly, so shade down; quarter-to-half Kelly on *cushion* is the sane band).

**Why it matters.** Sizing is where validation-grade math meets the binding physical constraint. Every strategy the pipeline certifies is worthless if the sizing layer lets one vol spike breach the trailing line. Note also the perverse trailing-drawdown geometry: pyramiding into a winner raises the peak (and thus the floor) before profits are banked — the MC funded-sim should specifically price this.

**Plugs in at:** sizing (cushion-proportional core rule + vol targeting overlay + fractional-Kelly cap); Monte Carlo funded-sim (already the right test harness — run candidate sizing rules through it and pick the one maximizing P(survive AND hit payout) rather than expected P&L); portfolio (cushion is a *shared* resource across strategies — see Section 6).

## 6. Portfolio Construction for a Book of Strategies — [PARTIAL — correlation battery supplies inputs; allocation logic is new]

**Plain terms.** Mean-variance (Markowitz) is theoretically optimal and practically fragile: it needs expected returns and an inverted covariance matrix, and tiny estimation errors in either produce wildly different, concentrated weights ("error maximization"). Hierarchical Risk Parity sidesteps both: cluster strategies by correlation, then split the risk budget top-down through the cluster tree — no matrix inversion, no return forecasts. Marginal contribution to risk (MCR) is the bookkeeping that tells you which strategy is actually spending your risk budget.

**Math intuition.** MV instability: weights w ∝ Σ⁻¹μ; when Σ is ill-conditioned (largest/smallest eigenvalue ratio large — guaranteed when strategies are correlated and history is short), inversion amplifies noise, so a small data change flips the whole allocation. HRP's three steps: (1) tree-cluster on distance d = √((1−ρ)/2); (2) reorder the covariance matrix so similar strategies sit adjacent (quasi-diagonalization); (3) recursively bisect the tree, allocating between the two halves by inverse variance. Works even on singular covariance matrices, and out-of-sample it beats both MV and naive inverse-vol in LdP's horse races. MCR: because portfolio vol σ(w) is homogeneous of degree one, Euler's theorem gives σ = Σᵢ wᵢ·∂σ/∂wᵢ — total risk decomposes *exactly* into per-strategy contributions RCᵢ = wᵢ(Σw)ᵢ/σ. Equal risk contribution (each strategy spends the same share of the book's vol) is the robust default for strategies with similar expected Sharpe.
*Why N mediocre uncorrelated strategies beat one great one*: with N uncorrelated strategies of equal Sharpe S, the book's Sharpe ≈ S·√N — three uncorrelated 0.8-Sharpe strategies ≈ one 1.4-Sharpe book. Same logic as Grinold's fundamental law (IR = IC·√breadth): breadth is a multiplier on skill. Under a *shared* $2k trailing line the effect is stronger than the Sharpe math suggests: drawdowns of imperfectly correlated P&L streams don't coincide, so peak book drawdown grows much slower than N while P&L grows with N — diversification is literally purchased survival probability. The trap: correlations spike in stress (tail dependence), so the √N benefit evaporates exactly when the line is near — which is precisely what the shop's tail-dependence stats and combined-ruin bootstrap already measure. Use those, not Pearson, as the diversification arbiter.

**Why it matters.** As the self-learning agent mints strategies, allocation across them becomes the dominant decision. The correlation battery already produces every input HRP needs; a strategy that adds Sharpe but raises combined-ruin probability is a *bad* addition — that acceptance rule is the portfolio-level counterpart of DSR.

**Plugs in at:** portfolio (HRP or ERC over the strategy book, fed by the existing correlation battery; MCR as the live risk-attribution dashboard); sizing (per-strategy risk budgets = MCR shares of the *cushion*, tying Sections 5 and 6 together); validation bars (new-strategy acceptance requires marginal improvement in combined-ruin bootstrap, not just standalone DSR).

## 7. Execution and Capacity — [NEW — mostly a backtest-realism standard, not a model]

**Plain terms.** At 1 NQ lot to 40 MNQ (≈ 4 NQ-equivalents), the shop has *zero* market-impact problem — NQ trades hundreds of thousands of contracts a day. The execution risk is entirely in *backtest assumptions*: what price you assume you got, whether limit orders you assumed filled would actually have filled, and whether spread + commission eats the per-trade edge. For a 1-minute-bar shop the whole game is: expected gross edge per trade must clear a realistic, itemized cost stack.

**Math intuition.**
- *Cost stack per round trip (taker)*: full spread (NQ spread ≈ 1 tick = 0.25 pts = $5 in RTH) + commissions/fees + occasional extra tick of slippage in fast tape. On 40 MNQ note the commission asymmetry: 40 micros ≈ 4 NQ in notional but ~10 contracts of commission per NQ-equivalent — micros are convenient for granular sizing and brutally expensive per notional. Model slippage as a *distribution* (0 ticks normal, 1–2 ticks in high-vol minutes, sized by the bar's range or vol regime), not a constant.
- *Maker vs taker corruption*: assuming limit fills whenever price *touches* your level is the classic backtest lie — you have a queue position, and price touching your bid fills the queue ahead of you first. Worse is adverse selection: the fills you *do* get cluster in the cases where price trades *through* your level — you get filled precisely when you're wrong (winner's curse). A maker-assumption backtest on 1-minute bars without queue modeling can turn a losing strategy into a "winner" purely via phantom spread capture. Honest tiers: (a) conservative default — assume taker, pay full spread both ways; (b) limit fills only when price trades *through* the level (not touches); (c) true queue-position simulation (needs L2/MBO data — likely overkill at this size). Bar-based fills add their own lies: "buy at bar close" hides intrabar adverse movement; never fill at mid.
- *Square-root impact law (conceptual)*: executing a metaorder of size Q moves price by ΔP ≈ Y·σ·√(Q/V) (Y ≈ 0.5–1, σ daily vol, V daily volume) — impact depends on the square root of *your size as a fraction of daily volume*, largely independent of execution schedule; concave and universal across asset classes. Intuition: your first contracts consume the liquidity that reveals nothing; each further increment digs into thinner book and signals more. For the shop: at Q/V ~ 10⁻⁵, impact is microscopic — but the law is the *scaling roadmap*: costs grow as √size, so a strategy's capacity limit is where σ√(Q/V) plus spread drag equals its per-trade edge. It also warns that thin sessions (overnight Globex) have a much smaller effective V — the same 4-lot clip is many multiples "bigger" at 3 a.m.

**Why it matters.** Refinement search will otherwise evolve strategies that exploit cost-model fiction — the highest-turnover, tightest-edge variants look best precisely because they harvest the largest amount of assumed-free spread. Cost realism is a *selection-pressure correction*, not an accounting detail.

**Plugs in at:** execution (itemized cost model: spread + commission + vol-conditional slippage distribution; taker-by-default policy); validation bars (no strategy passes on maker assumptions unless fills are trade-through-verified; report edge-after-costs at a pessimistic slippage percentile); refinement search (per-trade expected edge must clear the cost stack with margin — hard floor on acceptable expectancy per trade); Monte Carlo funded-sim (draw slippage from the distribution, not the mean).

## 8. Market Microstructure Signals — [NEW — feature source, with hard resolution caveats]

**Plain terms.** Order-flow imbalance (OFI): the net of aggressive buying vs selling (plus limit-order additions/cancellations at the touch) predicts — and largely *causes* — short-horizon price moves. VPIN: a "toxicity" gauge estimating how much of current flow is informed; when toxicity is high, market makers are being run over and liquidity is about to get expensive. At 1-minute resolution these are usable as *features and filters*, not as standalone alphas.

**Math intuition.** Cont–Kukanov–Stoikov: over short windows, ΔP ≈ β·OFI — a robust *linear* relation where β scales inversely with market depth (thin book → same imbalance moves price more). Crucial honesty: the strong relation is mostly *contemporaneous* (imbalance and the price move happen together); genuine *forward* predictability exists but is small, decays within seconds to a few minutes, and shrinks further once aggregated into 1-minute bars. So 1-minute CVD (cumulative volume delta — running sum of per-bar aggressor imbalance) is best used as: confirmation/divergence context (price up on shrinking delta = absorption), a meta-labeling feature, or an entry-timing tiebreaker — not a base signal expected to clear costs alone. NQ is actually the best case for this data: centralized CME tape with true aggressor flags, so CVD is clean (unlike tick-volume proxies).
VPIN: slice the tape into equal-*volume* buckets (volume clock — busy periods get sampled finer), classify each bucket's volume into buy/sell, and compute the average absolute imbalance |B−S|/(B+S) over a rolling window of buckets. High sustained VPIN (≳0.6 in the usual normalization) = persistent one-sided informed flow = elevated probability that liquidity provision breaks (documented running up to the 2010 flash crash). Caveat the literature honestly: Andersen–Bondarenko showed VPIN largely proxies for volatility/volume, so treat it as a refined *toxicity/regime filter*, not an oracle.
*What 1-minute depth/CVD data can and cannot support*: CAN — aggressor-imbalance features, absorption/divergence confirmation, toxicity/participation filters, session-context features (volume profile). CANNOT — queue-position alpha, sub-minute mean-reversion, iceberg/spoof detection, or anything relying on intra-bar event *sequencing*; a 1-minute bar erases the order in which flow arrived, and that ordering is where most tick-scale alpha lives. Those require full tick/MBO data and a queue-aware simulator (Section 7 tier c).

**Why it matters.** Microstructure features are the highest-plausibility *new feature family* for a 1-minute NQ shop — they carry information about *who is trading now*, orthogonal to price-derived features. Their correct role in this pipeline is as inputs to the meta-labeling/filter layer, where weak-but-real signals are most valuable.

**Plugs in at:** refinement search (OFI/CVD/toxicity as features for meta-labeling and regime filters — each feature family ledgered as trials); execution (VPIN-style toxicity filter for stand-aside periods and slippage-regime flags); validation bars (microstructure-driven strategies need tick-verified fill assumptions before promotion).

**Sources:** [Cont, Kukanov, Stoikov, "The Price Impact of Order Book Events"](https://www.researchgate.net/publication/47860140_The_Price_Impact_of_Order_Book_Events) · [Cross-impact of OFI in equity markets (Quantitative Finance)](https://www.tandfonline.com/doi/full/10.1080/14697688.2023.2236159) · [Order-flow filtration and short-horizon returns (arXiv)](https://arxiv.org/html/2507.22712v2) · [Fed note: OFI and price-move amplification in Treasuries](https://www.federalreserve.gov/econres/notes/feds-notes/order-flow-imbalances-and-amplification-of-price-movements-evidence-from-u-s-treasury-markets-20251103.html) · [Easley, LdP, O'Hara, VPIN paper (quantresearch.org PDF)](https://www.quantresearch.org/VPIN.pdf) · [Easley et al., "Flow Toxicity and Liquidity in a High Frequency World" (NYU PDF)](https://www.stern.nyu.edu/sites/default/files/assets/documents/con_035928.pdf) · [VisualHFT: VPIN explainer](https://www.visualhft.com/blog/volume-synchronized-probability-of-informed-trading-vpin/) · [Bookmap: CVD strategy and divergence](https://bookmap.com/blog/how-cumulative-volume-delta-transform-your-trading-strategy) · [United Daytraders: Delta & CVD limitations](https://united-daytraders.com/blog/delta-cvd-advanced-order-flow)

## 9. Stationarity and Edge Decay — [PARTIAL — era-splits detect decay retrospectively; live half-life monitoring is new]

**Plain terms.** Edges die. Four killers: *crowding* (others find it and arbitrage it away), *publication/diffusion* (the McLean–Pontiff result: documented anomalies lose roughly a quarter of returns out-of-sample and over half post-publication — decay is measurable and partly caused by awareness itself), *adaptation* (counterparties whose behavior you exploit change), and *structural change* (market plumbing changes — tick sizes, participants, microstructure regime). The operational questions are: how fast is *our* edge decaying (half-life), and has it *broken* (structural break) rather than merely drawn down?

**Math intuition.**
- *Half-life of an edge*: track a rolling edge metric — per-trade expectancy, rolling IC, or rolling Sharpe. Fit exponential decay E(t) = E₀·e^(−λt) → half-life = ln 2 / λ; or fit AR(1) with drift to the edge series, half-life = −ln 2 / ln φ. The estimate is noisy (the metric is itself a sample mean), so report it with a confidence band from the shop's existing bootstrap machinery; a half-life measurably shorter than the validation window is a red flag that the era-split pass was already stale at certification.
- *Structural breaks*: Chow (1960) tests a *known* break date via F-statistic; Quandt/sup-F handles a single *unknown* date; Bai–Perron finds *multiple* unknown breaks by globally minimizing squared residuals over break placements (supF(ℓ+1|ℓ) sequential testing). These are the forensic tools — for *live* monitoring the practical instrument is CUSUM on realized trade P&L against backtest-expected P&L: accumulate (realized − expected) per trade and alarm when the running sum crosses a boundary. This converts "is the strategy broken?" from a vibe into a stopping rule, and it distinguishes *drawdown consistent with the certified distribution* (Monte Carlo percentile bands answer this — the funded-sim already generates them) from *distributional change* (CUSUM/break tests answer this).
- *Decay-aware discipline*: era-splits are already an implicit decay test — comparing performance in later vs earlier eras estimates the decay slope for free; make that slope a reported statistic per strategy, not an incidental. And the self-learning loop must expect decay: capital allocation (Section 6) should tilt toward strategies with flat or unmeasurable decay slopes, and every strategy should carry ex-ante kill/probation criteria written down *at certification time* (e.g., "trailing 60-trade expectancy below the 5th percentile of the certified Monte Carlo null → probation; CUSUM alarm → demote to paper"). Deciding kill rules after the drawdown starts is just overfitting with extra steps, in reverse.

**Why it matters.** For a self-learning shop, decay monitoring closes the loop: discovery (Sections 1–3) → allocation (5–6) → execution (7–8) → *decay detection* → back to discovery. Without it the book silently fills with dead strategies that all passed validation once.

**Plugs in at:** validation bars (era-decay slope as a certification statistic; short measured half-life blocks promotion); portfolio (allocation tilted by decay slope; probation states); Monte Carlo funded-sim (certified P&L percentile bands double as live probation thresholds); refinement search (retirement of decayed strategies frees the trial budget — and re-discovered variants of a killed strategy inherit its ledger history, not a fresh trial count).
