## §0 — WHAT THIS REPLACES, AND WHY IT DOES NOT ARRIVE TRUSTED

This **replaces** the bundled `next_lvl_R ≥ 3R OR open space` gate as the
candidate. It is not an addition to it. If open-space confirms, the bundled
gate is superseded; if it does not, the bundled gate is not thereby
rescued — both fail together, because the bundled gate's measured value was
shown to come from this subset.

**It was found by taking apart something already published** (BR-32/35,
decomposed in FINDINGS-structural-target-exits §2). That is exactly the
provenance the programme treats as untrustworthy at face value. So the
confirmation step is not optional and is declared here, before any number
is read.

**What yesterday's §2 open-space numbers were computed under, stated
plainly** because it was not specified and it matters: **the V1 exit — the
shipped 75%@3R with the trail referencing the 15m BB MA.** Not V2, not a
structural target. The reported `+1.518R` (3m) and `+1.376R` (5m) are
shipped-exit numbers.

## §2 — THE CONFIRMATION, declared before the split is read

Frozen day-split, **seed 20260807**, defined over the **full fit day
universe** (not the population's own days, so the split does not move with
the population). Half 1 is the derivation half; Half 2 is the confirmation
half.

> **Declared bar.** Derive the base rate on **Half 1**. It confirms only if
> **Half 2 agrees in SIGN and its point estimate is at least HALF the Half-1
> magnitude**, with **both halves' day-boot CIs reported separately** —
> pooled is not a confirmation and will not be presented as one.

**Power is stated up front, not discovered afterwards:** the open-space
population is n≈87 (3m) and n≈100 (5m), so each half is **~43–50 rows**.
That is thin. The effect is large (~+1.4R), which is the only reason a
split-half is worth attempting at this n — and it is why the bar is
sign-plus-half-magnitude rather than "both CIs clear zero".
